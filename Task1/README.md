# Задание 1. Проверочный лист по безопасности данных PropDevelopment

## Описание

Данный документ содержит результаты анализа безопасности данных компании PropDevelopment в соответствии со стандартами ISO/IEC 27001 и 27002.

## Классификация данных

### 1. Публичные данные
**Описание:** Данные, доступные для широкой публики без ограничений.

**Примеры в PropDevelopment:**
- Информация о жилых комплексах (витрина продаж)
- Планировки и цены квартир
- Маркетинговые материалы

**Идентифицированные риски:**
- **Искажение данных** (ЗНАЧИТЕЛЬНЫЙ) - Неверная информация о ценах и планировках может привести к потере доверия клиентов и юридическим проблемам
- **Потеря данных** (НЕЗНАЧИТЕЛЬНЫЙ) - Публичные данные легко восстановить из резервных копий и источников

### 2. Внутренние данные
**Описание:** Данные для внутреннего использования компанией, не предназначенные для публичного доступа.

**Примеры в PropDevelopment:**
- BI и аналитические отчеты
- Данные о ремонтах и работах в ЖК
- Внутренние бизнес-процессы

**Идентифицированные риски:**
- **Утечка данных** (ЗНАЧИТЕЛЬНЫЙ) - Утечка аналитики может дать конкурентам информацию о стратегии и слабых местах
- **Некачественные данные** (ЗНАЧИТЕЛЬНЫЙ) - Некачественные данные в BI приведут к неправильным бизнес-решениям

### 3. Конфиденциальные данные
**Описание:** Данные, требующие защиты в соответствии с законодательством и политиками компании.

**Примеры в PropDevelopment:**
- Персональные данные клиентов (ФИО, телефон, email)
- Персональные данные собственников
- Данные бронирований и осмотров
- Платежная информация по ЖКУ
- CRM данные клиентов

**Идентифицированные риски:**
- **Утечка данных** (КРИТИЧЕСКИЙ) - Нарушение ФЗ-152 "О персональных данных" влечет штрафы до 500 тыс. руб. и репутационные потери. Зафиксированы случаи показа данных другого клиента!
- **Искажение данных** (КРИТИЧЕСКИЙ) - Искажение платежных данных приведет к финансовым потерям клиентов и судебным искам
- **Некачественные данные** (ЗНАЧИТЕЛЬНЫЙ) - Несколько точек регистрации клиента без координации создают дубликаты и противоречия

### 4. Секретные данные
**Описание:** Данные высшего уровня конфиденциальности, требующие максимальной защиты.

**Примеры в PropDevelopment:**
- Финансовая отчетность компании
- Учетные данные (пароли, токены)
- Ключи интеграций с госорганами
- API ключи платежных систем и партнеров
- Данные для онлайн-сделок

**Идентифицированные риски:**
- **Утечка данных** (КРИТИЧЕСКИЙ) - Утечка учетных данных и API ключей дает злоумышленникам полный доступ к системам. Отсутствует системный контроль!
- **Потеря данных** (КРИТИЧЕСКИЙ) - Потеря ключей интеграций парализует критичные бизнес-процессы (онлайн-сделки, платежи)
- **Обесценивание данных** (КРИТИЧЕСКИЙ) - Утечка финансовой отчетности даст конкурентам преимущество и может привести к рыночным манипуляциям
- **Искажение данных** (КРИТИЧЕСКИЙ) - Подмена данных онлайн-сделок может привести к мошенническим транзакциям и судебным искам

## Выявленные критические проблемы

На основе анализа текущей архитектуры PropDevelopment выявлены следующие критические проблемы:

1. **Отсутствие единой точки регистрации клиентов** - приводит к некачественным и противоречивым данным
2. **Отображение данных другого клиента** - критическая проблема с контролем доступа к персональным данным
3. **Отсутствие системного контроля за API партнеров** - риск утечки и несанкционированного доступа к данным
4. **Нет единых политик безопасности для интеграций** - различные уровни защиты в разных сервисах
5. **Недостаточный контроль передачи данных между доменами** - риск утечки конфиденциальной информации

## Рекомендации

1. Внедрить централизованную систему управления идентификацией и доступом (IAM)
2. Реализовать единую точку регистрации и управления данными клиентов (Master Data Management)
3. Разработать и внедрить политику классификации данных на основе ISO/IEC 27001
4. Внедрить API Gateway с контролем безопасности для всех партнерских интеграций
5. Провести аудит всех потоков данных и внедрить Data Loss Prevention (DLP)
6. Реализовать систему мониторинга и логирования доступа к конфиденциальным данным
